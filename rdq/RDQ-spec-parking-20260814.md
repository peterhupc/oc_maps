# RDQ 需求規格：parking 停車場地圖

## 一句話任務
第四張地圖 **parking**：一張跨縣市（分階段：先**北台3都**，驗證後再擴充其餘三都）的停車場地圖，**Google Places 提供點位**、**政府開放資料提供即時剩餘車位**，功能照 **foodmap** 模式（拖曳重搜＋分類＋收藏頁籤）。

## ✅ 已確認
- **範圍（分階段交付）**：第一階段先**北台3都**（台北/新北/桃園），**確認沒問題後**第二階段再擴充**台中/台南/高雄**；無即時資料的縣市顯示「僅基本資訊」或不收（Ⅲ）
- **點位來源**：**Google Places 為主**，沿用 foodmap 架構（Ⅲ）
- **即時車位**：要，採用**純靜態＋定時快取**——GitHub Actions 定時抓各縣市政府開放資料，打包成靜態 JSON（Ⅲ）
- **不做後端代理**：不用 Cloud Functions／Workers 常駐轉發（Ⅲ）
- **功能規模**：同 foodmap——**拖曳重搜、分類分組、收藏頁籤（含 Firebase 跨裝置同步）**（Ⅲ）
- 部署目標：**`https://peterhupc.github.io/oc_maps/parking/`**（Ⅰ/環境）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- **點位與即時車位的 join**：Google place 與政府停車場用「名稱＋座標」模糊比對，比對不到就只顯示 Google 基本資訊、不顯示車位 → 預設如此
- **抓取頻率**：六都更新頻率 1–3 分不等，快取統一 **每 10–15 分**抓一次 → 即時性以快取為準
- **收藏同步**：沿用 foodmap 的 Firebase 專案 **oc-maps-foodmap**，新增 parking collection（資料隔離用不同 collection）→ 預設如此；亦可新開專案
- **分類維度**：依「停車場類型」（路外／路邊）＋「收費／免費」混合分組，細類動工時再定 → 預設如此
- **Google API 費用**：個人使用流量低，免費額度內 → 不另付費
- **路邊格位 vs 路外場**：路邊車格（台中地磁、台北路邊）數量極大，第一版**優先路外停車場**，路邊格位延後 → 預設如此
- **第二階段時程**：台中/台南/高雄擴充**未排定**，第一階段北台3都驗收通過後才啟動 → 預設如此

## ➕ 已採納（象限Ⅳ）
- 顯示**收費資訊**（政府資料的 payGuide 費率文字）＋營業時間
- 快取頻率設計成**可調參數**（config 檔）
- 資料品質差的縣市**降級為僅基本資訊**，不讓半壞資料破壞體驗

## ❌ 排除項（明確不做）
- 不做後端代理／常駐伺服器（選定純靜態＋定時快取）
- 不做付費即時車位服務
- 第一版不收「路邊車格」動態資料（量大、欄位極度零散）
- 不做即時性保證（快取有 10–15 分延遲）

## 📋 一段式需求規格
建第四張地圖 **parking 停車場地圖**，部署於 **`/oc_maps/parking/`**。**分階段交付**：第一階段先**北台3都**（台北/新北/桃園），**驗證沒問題後**第二階段再擴充**台中/台南/高雄**。點位由 **Google Places API** 提供（沿用 foodmap 的 mapsLoader 模式），**即時剩餘車位**由 **GitHub Actions 定時抓取各縣市政府開放資料**（新北/桃園等，每 10–15 分）彙整成**靜態 JSON** 供前端讀取，兩者用名稱＋座標模糊比對 join，比對不到僅顯示 Google 基本資訊。功能照 **foodmap**：搜尋＋地圖、**拖曳重搜**、**分類分組**（停車場類型＋收費性質）、**收藏頁籤**（Firebase 跨裝置同步）。每張停車場卡顯示**剩餘車位、收費方式、營業時間**。無即時資料的縣市只顯示基本資訊。
