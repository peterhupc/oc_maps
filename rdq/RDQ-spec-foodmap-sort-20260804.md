# RDQ 需求規格：foodmap 結果排序

## 一句話任務
foodmap 搜尋出的餐廳列表，新增「排序」下拉選單，可依**距離／評分／價位**排序或維持 **Google 預設**。

## ✅ 已確認
- 提供 5 種排序選項，全部用下拉選單切換：**距離最近、評分最高、價位由低到高、價位由高到低、維持 Google 預設**（Ⅰ/Ⅲ）
- **距離基準＝搜尋輸入的地點**（非地圖中心、非固定台北）（Ⅲ）
- **收藏頁籤**套用與「全部」頁籤相同的排序（Ⅳ）
- **多重排序規則**：價位同級比評分、評分同級比距離（Ⅳ）
- 列表頂部顯示**目前排序方式**，可一鍵切回 Google 預設（Ⅳ）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- 距離方向＝**由近到遠**；不顯示實際公里數
- 距離基準只在「地址搜尋」時更新；拖曳重搜、首載自動搜尋不變更基準 → 預設如此
- **無評分（rating=0）**的店在評分排序時**排最後**；**無價位（price_level null）**的店在價位排序時**排最後**
- 排序選擇會**跨搜尋自然保留**（排序 state 常駐）；若想每次重搜重設回 Google 預設，可再改
- 排序為**純前端**處理，不影響後端查詢與 API 額度

## ➕ 已採納（象限Ⅳ）
- 收藏頁籤也套同一排序
- 多重排序規則（價位→評分→距離）
- 顯示目前排序方式＋一鍵回 Google 預設

## ❌ 排除項（明確不做）
- 不支援「人氣／熱門」排序（Google 無對應欄位，需另接數據）
- 不顯示距離數值，只排序
- 不做拖曳式手動排序
- 排序不影響地圖 marker 的生成順序（僅列表）

## 📋 一段式需求規格
foodmap 在餐廳列表（`PlaceList`）上方新增**排序下拉選單**，提供 5 個選項：**距離最近**（以**搜尋輸入的地點**為基準，由近到遠）、**評分最高**（由高到低）、**價位由低到高**、**價位由高到低**、**維持 Google 預設**（維持目前行為）。距離基準點只在使用者輸入地址搜尋時更新；**拖曳重搜**與**首載自動搜尋**不改變距離基準。排序同時套用於**全部**與**收藏**兩個頁籤。多重排序規則為：價位同級比評分、評分同級比距離；**無評分或無價位**的店家排最後。列表頂部以**小字顯示目前排序方式**，並提供一鍵切回 Google 預設。所有排序皆在**前端**處理，不影響既有 API 查詢。
